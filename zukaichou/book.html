はじめに

部品の名前を覚えると、Webサイト以外の画面もAIに頼めるようになる。

この言葉を覚える3つの理由

  • 一度覚えれば、サイトにもアプリにも通じる共通語になる
  • Web技術は公開された実例や解説がとても多く、AIの得意分野。名前で頼むほど答えが正確になる
  • 名前がわかれば、AIの答えを自分で検索して確かめられる

ミニ知識：Electron

VS Code や Slack は、Electron という仕組みで作られている。中身は Chrome と同じエンジンで動く Webページ。

試してみよう

VS Code で［ヘルプ］→［開発者ツールの切り替え］を開くと、Chrome と同じ開発者ツールが出てくる。

要素

第1章 箱のしくみ

ページを組み立てる部品1個分。タグで囲んだひとかたまり。

「上のほうの文字を大きくして」

→ 見出し・ロゴ・メニューのどれが変わるかわからない。

第1章 箱のしくみ

どの要素も中身・padding・border・marginの4層の箱。

× NG指示

「もうちょっと余白を空けて」

→ 内側か外側か、どの要素の余白かが伝わらない。

パディング

padding

第1章 箱のしくみ

箱の内側、枠と中身の間のすき間。

× NG指示

「ボタンをもうちょっと大きくして」

→ 文字サイズや幅まで変わり、思った形にならない。

○ 伝わる指示

「予約ボタンの文字サイズは変えずに、padding を上下16px・左右24pxに広げて」

.button {
  padding: 16px 24px; /* 上下 左右 */
}
関連：03 ボックスモデル ／ 05 margin7
05

マージン

margin

第1章 箱のしくみ

箱の外側、となりの箱との距離。

× NG指示

「カードの間をもっと空けて」

→ padding が増え、カードの中がスカスカになることがある。

○ 伝わる指示

「カード同士の間隔をmarginで24pxにして。カードの内側の余白は変えないで」

.card + .card {
  margin-top: 24px;
}

第2章 画面の部品

AIを使いこなす知恵 3／3

モックで見た目を決めてから、本番に頼む

付録

試行錯誤はモックで。本番には完成形だけを渡す。

○ モック用に頼む

「予約ページの見た目だけのモックを、1つのHTMLファイルで作って。保存などの動きはいらない」

○ 本番に頼む

「この画像と同じ見た目で予約ページを作って。今あるボタンとCSSを使い、新しい色は増やさないで」

こうする理由

  • 本番のコードが、試しては消す書き直しで散らからない
  • 見た目の正解が画像で決まるので、AIの答えがぶれにくい
  • 本番にはモックのコードを貼らず、画像だけを見せる。書き方が本番とずれて、混ざるのを防ぐ
